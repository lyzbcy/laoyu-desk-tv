# 自身更新

现状：0.3.7正式版，Windows真实正式源升级及故障注入恢复通过。
负责人：捞鱼。
最后更新：2026-10-10。

2026-10-13修复（正式0.3.7已验收）：成功查询的新版缓存持久化，同日冷启动披露“上次确认，更新前核实”；主窗口设置按钮显示轻量新版标记。缓存不能授权下载/安装，点击时仍强制重新查询正式源，失败保留提示和重试。冷启动显示上次失败，未确认恢复不能说已恢复。

Windows本轮助手核对卸载登记DisplayVersion/InstallLocation/DisplayIcon、开始菜单和已有桌面选项，IShellLinkW读取中文目标，失败还原原登记/链接和程序备份。新进程再独立核验实际登记/链接后才写restarted；模块从ASAR读取后复制到真实尝试目录运行。ready含版本和真实助手PID，并与引导器或子进程的PID一致才commit。Windows预检目录写权限；Mac spawn错误被接住，旧窗口保留。

旧0.3.3首次升级仍用其固化助手，其旧回退能力不能由新版元数据修复；本轮用0.3.6修复基线完成真实后续0.3.7升级与安装后故障注入。故障恢复核对原程序全量哈希、完整原HKCU登记和快捷方式字节；修复Copy-Item恢复已有目录产生嵌套的问题，恢复后核验原版本登记。正式源0.3.3→0.3.7同样通过，不能把新能力追溯到旧固化助手。最终CI/包和边界见standards-audit.md与verification/standards-2026-10-13。

按上海日期每天首次使用检查固定仓库正式Release，尝试/成功分别记入配置，失败不高频重试；手动检查可以重试。数字语义版本比较，只接收更高正式版本。

用户点击后下载对应平台/架构包，显示进度并验证GitHub原始SHA-256。成功后独立helper等待旧程序退出再更新，确认运行版本与路径；旧文件/设置保留恢复路径。失败提供重试及固定发布页。

Windows安装版使用NSIS；旧0.2.1便携版没有更新器，第一次手动安装。Mac无签名时不能声称系统自动更新框架可用，采用校验ZIP的独立更新路径并验证可写应用目录；首次打开遵循系统确认。

0.3.3改名：AppID、userData、稳定产品ID和userData保留；新仓库/包名使用laoyu-desk-tv，旧仓库仅保留旧客户端固化通道。Windows主exe改捞鱼桌脚看电视.exe，带薪看片.exe为有相同版本资源的精简转启动兼容入口，满足旧助手的文件检查。新运行进程只在同安装根目录、相同AppID/版本/token且旧名匹配时允许迁移重启回执，不能放宽到任意路径。Mac普通ZIP保存新app名称，另制作旧名包根目录的兼容更新ZIP；CFBundleIdentifier和版本相同，原目录可保留，但实际二进制/界面为新名。变更完成需旧0.3.2→0.3.3真实更新复验，不能用新客户端测试代替旧固化助手。

独立隐藏Windows助手需要执行策略Bypass（仅此进程）；等待主进程与同路径Chromium子进程退出，再执行NSIS，兼容四段版本资源。失败回执包含技术步骤、保留完整运行时备份；重启确认须版本/路径/token匹配。Mac助手校验ZIP及Bundle ID/版本，再在同盘替换应用并保留备份；尚未完成真机安装/回滚验收。
