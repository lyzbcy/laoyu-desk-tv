# 软件开发规范核查与修复

现状：修复与验证中，尚未发新版；负责人：捞鱼；最后更新：2026-10-13。

依据 E:/共享/tools/软件开发 下的软件组件、软件架构、推广&美化、测试和启动器适配规范。当前旧正式版0.3.3资产不覆盖；新代码、文档、版本、远端与正式包须同步。

| 规范 | 核查结果与处理 |
|---|---|
| 开发Skill、模块导航 | 已有SKILL/AGENTS、docs导航与模块文档；本轮补核查记录并同步真实状态。 |
| 每日更新、提醒、重试 | 已有上海日期尝试/成功、正式版本数字比较、SHA和重试。修复同日冷启动丢失已确认新版，显示“缓存待核实”；小窗设置按钮显示新版标记，安装仍强制实时查正式源。 |
| Windows安装重启门禁 | 原助手只验EXE版本；新助手与新版重启确认共同核对卸载登记、原目录、DisplayIcon、开始菜单及原桌面选项。读取IShellLinkW Unicode目标，不使用可能丢中文路径的WSH。 |
| 失败回退 | 原来仅恢复程序文件，登记/快捷方式可能保留新状态；本轮备份并恢复原登记与快捷方式，恢复结果明确留证，冷启动显示上次失败。不用“启动进程”冒充更新成功。 |
| 交接 | ready补状态、版本和PID，token/commit/abort继续严格；PowerShell模块写BOM并从真实文件运行，避免直接访问ASAR虚拟目录。 |
| 日志与等待反馈 | 播放/下载/安装已有阶段和进度。修复分享前再次解析旧日志，只保留有限事件及按字段约束的技术信息，限制读取量；不导出未知文字、用户路径/网址/凭据。 |
| 用户反馈 | 原为复制后手动粘贴。用户已选择预填GitHub：先预览实际正文及诊断内容，默认生成独立ZIP可取消，打开预填表单由用户确认公开提交；长备注明确复制回退，不截断。失败保留备注，重试不重复生成附件。没有发送真实验收消息。 |
| 求评价与Star | 原为所有用户均显示静态Star请求。本轮改为累计3个上海日期后、用户主动进入设置才展示；关闭后至少15天不再提示，回拨时钟不能绕过。无启动营销弹窗。 |
| 美化与Logo | 原安装器已采用WPF无白标题栏、盘符按钮、非系统盘建议和自选路径。沿用注册表中的独立偷看表情Logo，设置页补原创图标及主题预览；不重复占用其他产品Logo。 |
| Windows/Mac架构 | 共享纯业务、独立平台构建。Mac真人听音、全屏/全局键、安装更新回滚限制继续明确，不能由Windows或CI代替。 |
| 启动器适配 | 稳定paid-to-watch ID、AppID/userData及旧名称兼容入口保留；新包须严格自查与真实下载/识别/打开，官网同址同步。 |
| 回归规范 | 隐藏、隔离真实Electron IPC与本地媒体验证；Kimi子Agent观察隔离网页夹具并记录边界。修复smoke主动showInactive和重复开设置时show/focus、真实托盘副作用。 |

GitHub诊断ZIP需要用户在反馈页拖入附件，不能称为企微直送或自动提交。机器人密钥不进入公开客户端；该选择来自用户本次明确回复。任意未知旧日志不能承诺绝对“无敏感信息”，应以实际预览和有限字段过滤为准。

发布前还须实际打包验证、Windows完整安装版升级/可见重启/桌面重开及故障恢复。原0.3.3已固化旧助手，只能验证它自己的链路，不能用更新元数据补修其已固化逻辑；新助手须另做真实后续升级测试。所有命令、CI与哈希以verification/standards-2026-10-13为准。
